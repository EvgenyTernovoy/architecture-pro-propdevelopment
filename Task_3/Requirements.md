# Требования к безопасности

1. Использовать TLS (SIPS, HTTPS) для SIP, REST API
2. Не допускать «чистого» SIP без шифрования
3. Для авторизации через API использовать OAuth 2.0 / OpenID Connect
4. Каждое устройство должно иметь свой уникальный ключ/токен.
5. При удалении пользователя из системы его ключи/токены должны немедленно терять силу.
6. Логирование всех действий (открытие двери, вход в приложение, вызовы через SIP)
7. Все вызовы должны идти через API-шлюз

# Как работает интеграция

- Внешняя платформа выполняет только технические функции: принимает звонок, передаёт событие, открывает замок.
- Предприятие остаётся владельцем правил доступа: хранит список пользователей, их права, квартиры, роли.

## Схема взаимодействия

1. Событие (например, «звонок на панель» или «попытка открыть дверь») возникает во внешней системе.

2. Платформа отправляет запрос на авторизацию во внутреннюю систему (через API Gateway).

3. Запрос может содержать только минимальный идентификатор (например, ID домофона, ID ключа, хэш токена).Без ФИО, номера квартиры и других персональных данных.

4. Внутренняя система проверяет правила доступа и принимает решение «разрешить / запретить».

5. Ответ возвращается на внешнюю платформу, которая выполняет действие (открывает или блокирует).

6. Все события логируются в корпоративной SIEM.
